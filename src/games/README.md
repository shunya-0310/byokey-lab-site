# 1868 交渉エンジンと振り返り

## 状態の境界

- 通常会話は1ターンにつきGemini APIを1回呼ぶ。同じ応答で発言、意味イベント、獲得情報、新政府側の実行可能性評価を受け取る。
- JSON Schemaとクライアントの検証を通ったイベントだけを、決定的なReducerに渡す。検証失敗時は発言・台帳とも反映しない。自動再試行はせず、プレイヤーが再送できる。
- `canonicalLedger.proposals/events`が合意の正本。`issues`と画面用台帳は派生値。受信時とReducerの正規化は同じ形式を再入力してもID・依存条件を失わない。
- 旧セーブとの互換性のため `agreed` / `tentatively_agreed` と9論点のIDを維持する。`peaceful_transition`が指示書の`transition`に対応する。治安・市民保護・無血移行を同時に扱う発言は、意味イベントで該当する全論点を記録する。
- Packageのacceptは全対象論点へ適用する。条件の一部だけを確認した場合、関係のない未決提案を消さない。依存条件は確定合意を起点とする固定点計算で解決し、循環依存を確定合意としない。
- 決着と反芻はCanonical Stateのみを読み、会話の再解釈もAPI呼び出しも行わない。NOT_READYの発言は実際の未決論点に限定する。勝海舟が受諾した決着の再評価は合意を取り消さない。
- 新政府判定は勝海舟の受諾後のみ実行する。政府受諾・信頼性・整合性が低い場合も合意済み論点を未解決へ戻さない。政府承認待ちの上申と、個人による越権保証を別評価する。

## 結末と記録

- Ending → 「交渉を振り返る」 → Review → 「もう一度、三月十四日へ」。Reviewはアプリ内の画面であり、専用URLには依存しない。
- 結末確定時に会話、取得済み情報、結末本文、日時をコピーしてfreezeし、進行中セーブとは別の`completed-run`に保存する。保存失敗は画面に表示する。
- 最終決着の要求と勝海舟の返答も会話履歴へ含める。Reviewで新しい攻略情報や内部数値を開示しない。
- 再挑戦は進行中の交渉を初期化する。前回の完成記録は次の結末まで維持し、タイトルから参照できる。

## 検証

```powershell
npm.cmd run test:edo
npm.cmd run test:edo:live
npm.cmd run build
```

ライブテストは環境変数`GEMINI_API_KEY`を使用する。ブラウザ保存キーを読み取らない。`test-results/edo-1868-live-report.json`に会話・台帳・判定を保存するが、キーや認証ヘッダは保存しない。

2026-09-22〜23の検証では、協調Package、新政府承認、強硬決裂、添付会話に基づく治安引継ぎと政府承認待ち、裏付けのない過大保証の5シナリオを確認。単体テストは受信処理を通す回帰テスト、短い受諾、曖昧な対象、依存条件、明示的撤回、原子的検証、決着の再評価、新政府判定の分離、Snapshotの独立性を含む。

## 制約

- 自由文の意味抽出と実行可能性の評価にはモデルの揺らぎが残る。抽出の形式と参照先の不整合は検証で止め、過去の合意を後から自由に再判定しない。
- 旧版ですでに記録から欠落した合意は、会話を再解釈して自動復元しない。既存台帳にある合意を保持して移行する。
- モバイル検証はブラウザの320/360/390/412/430px幅とPC幅。Android実機のソフトキーボードやブラウザバーの挙動は未検証。

## Ending / Review / Replay（2026-09-23）

結末は `edo1868-ending.js` がCanonical Stateから固定したSettlementSnapshotを使って描写する。受諾済みの約束と履行済みの出来事を区別し、エンディング用の追加LLM呼び出しは行わない。

- `/games/edo-1868/ending`: 最新のCompletedRunの結末。
- `/games/edo-1868/review`: 同じ記録の結末要約、発見済みノート、時系列の会話。
- 再挑戦は進行中のゲームだけをリセットする。直前のCompletedRunは保持する。
- リロード・直接アクセスでは保存した記録を表示する。記録がない場合はタイトルへ戻る導線を表示する。
- 旧記録は保存済みの結末を維持して移行する。過去の会話から約定を推測し直さない。

`npm.cmd run test:edo` は結末Snapshotの回帰テストも実行する。画面検証は `node scripts/create-edo-ending-fixture.mjs` 実行後、Viteの `/test-results/edo-ui-fixture.html` から開始できる。合意済み再現データで、決着要求 → 政府判断 → 結末 → レビューの全履歴展開 → 再挑戦まで確認する。このローカル検証ページは本番ビルドに含まれない。

## 一発勝負の決着（2026-09-25）

- NOT_READYのみ通常交渉を継続できる。ACCEPTED後は条項変更・会話・再審査を禁止し、政府の承認／不承認から直接結末へ進む。再読み込み後も確定状態を維持する。
- 政府の条項別審査と内部根拠は保持する。結末・レビュー・保存済み記録の表示には承認結果だけを渡し、修正案は公開しない。
- 今回の検証は指示により外部LLM APIを使用せず、上記3ケースの決定的テスト、関連テストとビルドのみ実施する。
