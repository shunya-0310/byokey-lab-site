# 無血開城ルート調査・限定修正（2026-09-25）

## 結論と証拠の範囲

今回の実プレイのCanonical Ledger・Gemini応答・CompletedRunは取得していない。ユーザーの説明を手動で構造化した条項による検証であり、実プレイの原因の確定ではない。

コードで確認できた不具合は、選抜的な登用の検討だけでも財源の保証を要求する `support_funding` 判定である。採用・支払の確約がない努力義務を、支出義務と混同していた。これを修正した。

今回の再構成では修正前後とも不承認となる。ただし過大保証とは理由が異なる。限定的支援を無制限負担へ分類する処理や、裁可留保自体を拒否する処理は確認されなかった。

## 保存・抽出の対応

既存の条項ID、原発言、版管理、変更継承の処理は変更していない。抽出スキーマの説明だけを明確にした。実LLMがこれらを正しく抽出するかは未検証である。

## 政府審査の比較

- 過大保証：`land_scope`、`stipend_capacity`、`appointment_capacity`、`fiscal_limit`、`combined_obligations`、`fleet_control` により不承認。権限属性だけを裁可留保へ置き換えても、過大な義務の審査は残る。
- 今回の再構成：`support_funding` と `fleet_control`。修正後、前者の対象は生活支援条項のみで、登用検討条項は対象外となった。
- 既存の実行可能な和平条項は承認を維持。登用検討だけの条項を財源未記載にしても、それだけで拒否しないことを確認。
- 開発者向け比較として、再構成条項に生活支援の予算制限と移管までの共同監督を明示した別案は承認された。これは今回の会話に存在した条件という主張ではなく、一般ルールで成功経路が残ることの確認である。

財源要件と移管までの監督要件は、現行ゲームの政策ルールである。史実上その明示が必須だった、あるいは今回の約定が客観的に履行不能だったと断定するものではない。指示に従い今回の結果だけを成功へ変えるための緩和はしていない。

「双方立会いの封印」が実データで `fleet_oversight:joint` に抽出されていれば、軍艦の不承認理由は消える可能性がある。支援財源が別の合意・明示依存として保存されていれば、財源理由も異なる。正確な原因確定には実プレイの条項と保存済み審査根拠が必要。

総攻撃の猶予／中止は独立した構造化属性・政府判定項目ではなく、今回の不承認をその違いで説明する根拠はない。武装解除確認後の城引渡しと、城明渡しに合わせた軍艦移管は現行の引渡し要件を満たす。
